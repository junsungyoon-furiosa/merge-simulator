# PR 병합 전략 시뮬레이터 요구사항 명세

> 상태: 요구사항 확정 완료
> 최종 정리일: 2026-09-01
> 목적: 구현 계획을 세우기 전에 시뮬레이터의 책임, 환경 규칙, 정책 인터페이스, 출력 지표를 확정한다.

## 1. 프로젝트 목표

지속적으로 도착하는 PR을 하나의 CI 자원으로 검사하는 상황을 시뮬레이션한다. 사용자가 환경 조건과 운영 정책을 입력하면, 시뮬레이터는 해당 조합을 실행하고 안전성·속도·처리량·자원 사용 결과를 정량적으로 출력한다.

```text
환경 조건 + 운영 정책 + 난수 시드
→ 시뮬레이션 실행
→ 이벤트 로그 + 결과 지표
```

시뮬레이터의 역할은 정책을 실행하고 결과를 측정하는 것까지다.

### 1.1 하지 않는 일

- 허용 가능한 결함 PR 유입률을 정하지 않는다.
- 특정 정책을 최선 또는 부적합으로 자동 판정하지 않는다.
- 현실 지표를 수집하거나 실제 확률을 추정하지 않는다.
- 실제 master 복구, 롤백 또는 수정 PR 재투입을 모델링하지 않는다.
- 여러 LLM의 내부 병렬화나 합의 과정을 별도로 모델링하지 않는다.

## 2. 상태와 용어

### 2.1 PR 결함

- **개별 결함 PR**: 다른 PR과 관계없이 후보 master를 비정상으로 만드는 PR이다.
- **상호작용 결함 집합**: 구성 PR이 모두 함께 있을 때 후보 master를 비정상으로 만드는 최소 실패 집합이다.
- 상호작용 결함 집합의 크기는 2 이상이며 3개 이상의 PR도 포함할 수 있다.
- 상호작용 결함 집합에서 하나 이상의 PR을 제거한 진부분집합은 해당 상호작용 원인에 대해서는 정상이다.
- 하나의 배치에는 여러 개별 결함 PR과 여러 상호작용 결함 집합이 동시에 존재할 수 있다.

### 2.2 후보 master

`후보 master`는 현재 master에 CI 대상 배치의 모든 PR을 가상으로 머지한 상태다.

- 후보 master가 정상이면 CI의 기본 판정은 성공이다.
- 후보 master가 비정상이면 CI의 기본 판정은 실패다.
- 실제 정상 여부는 시뮬레이터 내부 정답이며 정책과 LLM에는 공개하지 않는다.
- 정책과 LLM은 CI 관측 결과와 추상화된 실패 힌트만 볼 수 있다.

### 2.3 PR 상태

| 상태 | 의미 | 종료 상태 |
|---|---|---:|
| 대기 | 아직 CI 배치에 배정되지 않은 PR | 아니요 |
| CI 대기 | CI 실행을 기다리는 배치에 포함된 PR | 아니요 |
| CI 실행 | 현재 CI가 검사 중인 배치에 포함된 PR | 아니요 |
| 조사 | 실패한 배치에 속해 후속 정책 결정을 기다리는 PR | 아니요 |
| 의심 | LLM이 범인 후보로 지목한 PR | 아니요 |
| 머지 | master에 머지된 PR | 예 |
| 격리 | 단독 CI 실패로 격리된 PR | 예 |

머지 또는 격리된 PR은 시뮬레이션이 끝날 때까지 다시 테스트하거나 상태를 변경하지 않는다.

## 3. 시뮬레이터 엔진의 고정 규칙

### 3.1 PR 도착과 숨겨진 정답 생성

- PR은 시뮬레이션 도중 계속 도착한다. 모든 날은 동일한 평일로 취급하고 주말과 휴일은 모델링하지 않는다.
- 사용자는 근무일당 평균 PR 생성 수를 입력하며 실제 시간대별 생성 수는 포아송 분포로 변동한다.
- KST 00시부터 23시까지의 가중치는 `[60, 19, 4, 4, 0, 5, 7, 10, 31, 68, 167, 210, 164, 301, 268, 276, 310, 316, 256, 259, 244, 160, 102, 93]`을 사용한다.
- 각 PR의 정확한 도착 시각은 선택된 시간 안에서 균등하게 추첨하며 첫 PR도 0분에 강제로 생성하지 않는다.
- CI는 PR 도착 시간대와 관계없이 24시간 계속 작동한다.
- 실패 배치를 조사하는 동안에도 새 PR은 계속 도착한다.
- 대상 PR 생성기는 개별 결함 PR과 상호작용 결함 집합을 생성한다.
- 생성된 결함 정보는 정책에 숨기고 시뮬레이터의 정답 데이터로만 보관한다.
- 같은 환경 입력과 난수 시드는 같은 PR 도착 및 결함 상태를 재현해야 한다.

### 3.2 CI 자원과 실행시간

- CI 실행 도구는 하나뿐이며 동시에 하나의 배치만 검사할 수 있다.
- CI 실행시간은 CI가 관측한 성공 또는 실패 결과에 따라 서로 다른 로그정규분포에서 결정한다.
- 각 분포는 중앙 확률 구간의 하한·상한·포함 확률로 정의하며, 포함 확률은 사용자가 편집하지 않는 시나리오 값으로 저장한다. 기본 포함 확률은 95%다.
- 관측 성공이면 성공시간 구간, 관측 실패이면 실패시간 구간을 사용하므로 CI 오판도 관측 결과에 해당하는 시간을 사용한다.
- CI 실행시간은 배치 크기의 영향을 받지 않는다.

### 3.3 CI 오판

- 거짓 음성률과 거짓 양성률을 사용자가 환경값으로 입력한다.
- 두 오류율은 배치 크기, 결함 수, 결함 종류와 관계없이 모든 CI 실행에 동일하게 적용한다.
- 동일 배치를 재실행하더라도 각 실행의 오판 여부를 독립적으로 다시 추첨한다.
- 거짓 음성으로 비정상 후보 master를 성공으로 판정할 수 있다.
- 거짓 양성으로 정상 후보 master를 실패로 판정할 수 있다.

### 3.4 CI 결과에 따른 자동 상태 전환

- CI 성공 시 배치의 모든 PR을 정책의 추가 결정 없이 즉시 원자적으로 머지한다.
- 성공이 거짓 음성이어도 동일하게 즉시 머지한다.
- PR 하나만 포함된 단독 CI가 실패하면 해당 PR을 즉시 격리한다.
- 단독 실패가 거짓 양성이어도 동일하게 격리한다.
- 둘 이상의 PR이 포함된 CI가 실패하면 해당 PR들을 조사 상태로 보내고 다음 행동을 정책에 요청한다.
- 정책은 PR을 직접 머지하거나 격리할 수 없다.

### 3.5 Master 버전과 CI 유효성

- CI 실행은 시작 시점의 master 버전을 기준으로 한다.
- CI 실행 중 master가 변경되면 해당 실행 결과는 무효다.
- 무효화된 실행도 CI 사용시간과 실행 횟수에 포함한다.
- 무효화된 배치를 언제 다시 검사할지는 정책이 결정한다.

### 3.6 비정상 master

- 거짓 음성으로 결함 배치가 머지되면 master는 비정상 상태가 된다.
- 비정상 master는 자동 복구되지 않으며 시뮬레이션은 계속 진행한다.
- 이후 후보 master는 비정상 상태를 이어받으므로 CI의 기본 판정은 실패다.
- 추가 거짓 음성이 발생하면 비정상 master에도 PR이 계속 머지될 수 있다.
- 복구 PR, 롤백 및 외부 복구 사건은 모델링하지 않는다.

### 3.7 실패 힌트

- CI 실패 시 실패 힌트 또는 테스트 결과가 생성된다.
- 구체적인 테스트명, 내용, 정보량은 모델링하지 않는다.
- 실패 힌트는 LLM 입력에 포함되는 불투명한 추상 정보다.
- 힌트의 유용성은 LLM 정확도 환경값에 포함된 것으로 본다.

### 3.8 LLM 탐정

- LLM은 CI가 실패한 배치에 대해서만 호출할 수 있다.
- 입력은 실패 배치의 모든 PR과 해당 CI 실행의 실패 힌트다.
- 출력은 범인으로 판단한 PR 집합이며 빈 집합도 가능하다.
- 여러 후보를 반환할 수 있지만 순위나 점수는 반환하지 않는다.
- 여러 LLM의 내부 합의는 하나의 추상화된 LLM 성능으로 표현한다.
- 서로 다른 실패 배치의 LLM 요청은 자원 경합 없이 동시에 실행할 수 있다.
- LLM 실행시간도 CI와 같은 중앙 확률 구간 기반 로그정규분포로 결정하며, 구간 포함 확률은 실험 스냅샷에 저장한다.
- 실제 범인 지목 확률과 정상 PR 오지목 확률을 별도 환경값으로 입력한다.
- LLM이 지목한 PR은 의심 상태가 된다.
- LLM 판단만으로 PR을 격리할 수 없다. 격리에는 반드시 단독 CI 실패가 필요하다.
- LLM 출력 이후의 후속 CI 구성은 정책이 결정한다.

### 3.9 LLM 결과 평가

한 배치의 개별 결함 PR과 최소 상호작용 결함 집합을 각각 하나의 실패 원인으로 센다.

- 개별 결함 원인은 해당 PR을 LLM이 지목하면 발견한 것으로 본다.
- 상호작용 결함 원인은 LLM 출력이 해당 집합과 하나 이상 겹치면 발견한 것으로 본다.
- `원인 커버리지 = 발견한 실패 원인 수 / 전체 실패 원인 수`로 계산한다.

| 등급 | 정의 |
|---|---|
| 성공 | 원인 커버리지 100% |
| 부분실패 | 원인 커버리지 0% 초과 100% 미만 |
| 실패 | 원인 커버리지 0% |

CI 거짓 양성으로 실제 실패 원인이 없을 때는 빈 집합 반환을 성공, 하나 이상의 PR 지목을 실패로 본다. 정상 PR 오지목은 위 등급과 별도 지표로 기록한다.

### 3.10 종료 조건

다음 중 하나가 발생하면 즉시 종료한다.

- 사용자가 시뮬레이션을 중단한다.
- 전체 머지 PR 수가 사용자가 지정한 목표값에 도달한다.

종료 시 대기·검사·조사 중인 PR은 추가 처리하지 않고 현재 상태 그대로 결과에 포함한다.

## 4. 엔진과 입력 정책의 경계

### 4.1 엔진이 담당하는 것

- 시간과 사건 진행
- PR 도착 및 숨겨진 결함 상태 생성
- 단일 CI 자원과 LLM 실행
- CI 및 LLM의 확률적 관측 결과 생성
- master 버전 및 정상 상태 관리
- 자동 머지·격리·의심 상태 전환
- 이벤트 로그 및 지표 계산

### 4.2 정책이 담당하는 것

- CI에 제출할 PR 배치와 제출 시점
- 실패 배치의 분할 방법과 검사 순서
- LLM 호출 여부
- LLM 결과 이후 의심 PR과 나머지 PR의 후속 CI 구성
- CI를 비워두고 추가 PR을 기다릴지 여부
- 여러 대기 배치의 우선순위

정책이 선택하지 않은 후속 행동을 엔진이 임의로 대신 결정하지 않는다.

### 4.3 정책 인터페이스 초안

```text
입력:
  현재 시각
  관측 가능한 PR 및 배치 상태
  CI 자원 상태와 과거 관측 결과
  추상 실패 힌트
  사용 가능한 LLM 결과

출력:
  CI 배치 제출
  LLM 호출
  대기
```

정책은 숨겨진 결함 정보, 상호작용 집합, 후보 master의 실제 정상 여부 및 미래 난수를 볼 수 없다.

정책은 머지·격리되지 않았고 다른 CI 또는 LLM 실행에 점유되지 않은 PR 중 임의의 부분집합을 다음 CI 배치로 선택할 수 있다. 대기·조사·의심 상태의 PR이 선택 대상에 포함된다.

CI가 비어 있고 검사 가능한 PR이 존재하더라도, 정책은 더 많은 PR을 기다리기 위해 `대기` 행동을 선택할 수 있다.

### 4.4 첫 버전의 기준 정책

현재는 다음 세 기본 정책과 하나의 추가 Bors 기준 정책을 제공한다. 추가 정책은 같은 인터페이스로 확장한다.

1. PR을 하나씩 검사하는 순차 CI 정책
2. 고정 크기 배치가 실패하면 하위 배치로 분할하는 CI 전용 정책
3. 실패 후 LLM 결과를 활용해 후속 CI 배치를 구성하는 LLM 보조 정책
4. 실제 bors의 핵심 배치·이분할 흐름을 현재 시뮬레이션 범위로 추상화한 Bors 기준 정책

Bors 기준 정책에서 PR 도착은 r+ 승인 후 병합 큐 등록을 뜻하며 다음 규칙을 사용한다.

- 첫 PR이 waiting 배치를 만든 시점부터 batchDelay를 계산하고, 후속 PR이 합류해도 타이머를 초기화하지 않는다.
- maxBatchSize는 배치 상한이며, 상한 도달 자체는 즉시 CI 실행 조건이 아니다.
- CI 실행 중 도착한 PR은 실행 중인 배치를 변경하지 않고 별도 waiting 배치에 쌓는다.
- 유한한 실행을 마무리하기 위해 모든 PR이 도착한 뒤에는 남은 신규 PR 부분 배치의 지연만 생략한다.
- 실패한 다중 배치는 앞쪽이 하나 더 크도록 정확히 절반으로 나누고 왼쪽 하위 배치부터 생성한다.
- 분할 하위 배치도 실패 시점부터 새 batchDelay를 적용한다.
- splitBatchScheduling=fifo는 모든 waiting 배치를 생성 순서로 처리하고, beforeFresh는 실행 가능한 분할 배치를 신규 PR 배치보다 먼저 처리한다.
- 단일 PR CI 실패는 공통 엔진 규칙에 따라 격리하며 Bors 정책은 LLM을 사용하지 않는다.

배치 크기, 분할 비율, 대기시간, LLM 결과 활용 순서 같은 구체적인 정책 매개변수와 알고리즘은 구현 계획에서 명세한다.\n\n정책 종류는 중앙 레지스트리에 등록하며, 사용자는 등록된 정책을 비교 목록에 추가·제거·복제할 수 있다. 같은 정책 종류도 서로 다른 설정과 고유 인스턴스 ID로 여러 번 비교할 수 있다. 한 실험의 정책 목록에는 하나 이상의 정책 인스턴스가 필요하며 제품 기능상 최대 개수는 고정하지 않는다.

## 5. 환경 입력

현실에서 정확한 값을 확보하는 일은 범위 밖이다. 사용자가 값을 바꾸어 시나리오를 구성할 수 있어야 한다.

| 영역 | 환경 입력 | 상태 |
|---|---|---|
| PR 도착 | 근무일당 평균 PR 생성 수 | 사용자 입력, 실제 일별·시간대별 생성 수는 확률적으로 변동 |
| 개별 결함 | 결함 PR 생성 확률 또는 개수 | 입력 필요·형식 구현 위임 |
| 상호작용 결함 | 발생 빈도, 조합 크기 분포, 최대 크기 | 입력 필요·형식 구현 위임 |
| CI 시간 | 관측 실패·성공별 중앙 확률 구간 하한·상한 | 사용자 입력, 포함 확률은 코드 기본값을 스냅샷에 저장 |
| CI 정확도 | 거짓 음성률, 거짓 양성률 | 확정 |
| LLM 정확도 | 실제 범인 지목 확률, 정상 PR 오지목 확률 | 확정 |
| LLM 실행 | 중앙 확률 구간 하한·상한 필수, 포함 확률은 코드 기본값을 스냅샷에 저장, 호출 금액 선택 | 확정 |
| 실행 조건 | 목표 머지 PR 수, 난수 시드, 반복 횟수 | 일부 확정 |
| 운영 정책 | 배치·분할·대기·LLM 사용 규칙 | 정책 입력 |

모든 입력값과 난수 시드는 실행 결과와 함께 저장하여 같은 조건을 재현할 수 있어야 한다.

### 5.1 환경값 근거와 보정 프로필

- UI는 근무일당 평균 PR 생성 수, 개별 결함률, CI 실패·성공 시간 구간, CI 거짓 음성·양성률, LLM 적중·오지목률, LLM 시간 구간의 현실 의미와 시뮬레이션 의미를 설명한다.
- 각 항목은 문서 작성 상태와 관측·추정값 상태를 별도로 표시하며, 값이 미산출이면 적용할 수 없다.
- 근거 프로필의 관측·추정값은 확인 다이얼로그에서 현재값과 비교한 뒤 개별 또는 일괄 적용한다.
- 첫 Bors 운영환경 프로필은 아홉 항목의 근거 초안만 제공하고 관측·추정 숫자는 포함하지 않는다. 실제 데이터 수집과 자동 산출은 범위 밖이다.
- 적용한 항목은 프로필 ID, 프로필 버전과 적용 당시 값을 시나리오 스냅샷에 보존한다. 이후 수동 수정은 허용하며 UI에서 적용 후 수정 상태로 구분한다.
- 출처 메타데이터는 시뮬레이션 난수 소비, 이벤트와 지표에 영향을 주지 않는다.
- 시나리오 저장 형식은 최초 공개 schema v1만 지원한다. 개발 중 사용한 이전 형식과 브라우저 저장 데이터와 JSON은 폐기한다.

## 6. 출력과 지표

### 6.1 필수 지표

| 영역 | 지표 |
|---|---|
| 안전성 | 결함 PR 유입률, 유해 상호작용 조합 유입률, master 비정상 진입 횟수 |
| 머지시간 | 정상 PR 평균·최소·최대·P50·P90·P95·P99·분산 |
| 처리량 | 단위 시간당 전체·정상·결함 PR 머지 수 |
| 격리 | 격리 PR 수, 정상 PR 오격리 수, 격리까지 걸린 시간과 분포 |
| CI | 실행·성공·실패·재실행·무효화 횟수, 사용률, 유휴시간 |
| 대기열 | 평균·최대 길이, 평균·백분위 대기시간 |
| LLM | 호출 수, 성공·부분실패·실패, 원인 커버리지, 정상 PR 오지목률, 실행시간 |
| 비정상 master | 지속시간, 해당 상태에서의 CI 횟수와 추가 머지 수 |
| PR 상태 | 대기·CI 대기·CI 실행·조사·의심·머지·격리 상태별 수와 비율 |
| 비용 | CI 및 LLM 비용. 비용 입력을 제공할 때 계산 |

결함 PR 유입률은 다음과 같이 계산한다.

```text
결함 PR 유입률 = 머지된 결함 PR 수 / 전체 머지된 PR 수
```

분모가 0인 실행의 표현 방식은 구현 단계에서 정한다.

### 6.2 이벤트 로그

모든 요약 지표는 원시 이벤트 로그에서 파생 계산한다. 이벤트 로그는 최소한 다음을 포함한다.

- 실행·시나리오·정책 ID와 난수 시드
- 사건 시각과 사건 종류
- 관련 PR·배치·CI·LLM ID
- 사건 전후의 PR·배치·master 상태
- 대기·검사·LLM·머지·격리에 사용된 시간
- 후보 master의 실제 정상 여부와 CI 관측 결과
- 실제 실패 원인과 LLM 출력 집합
- 발생 비용과 사용 자원

### 6.3 결과 표현 후보

- 정책별 지표 비교표
- 평균·백분위·최악 구간 그래프
- 안전성과 속도의 파레토 프런티어
- 특정 실행의 사건 타임라인
- 입력 민감도 분석
- 설정과 결과의 CSV/JSON 내보내기

결과 표현 형식과 웹 UI는 구현 계획 단계에서 설계한다.

## 7. 시뮬레이션 방식

### 7.1 구현 방향

- PR 도착, CI 시작·완료, LLM 완료, 머지, 격리를 사건으로 처리하는 이산사건 시뮬레이션을 사용한다.
- 동일 조건을 여러 난수 시드로 반복하는 몬테카를로 실험을 지원한다.
- 정책 비교 시 가능한 한 동일한 PR 도착·결함 사건과 난수 스트림을 공유한다.
- 구체적인 확률분포와 기본 반복 횟수는 구현 단계에서 결정한다.

### 7.2 기술 구조

- 첫 버전은 별도 애플리케이션 서버 없이 브라우저에서 실행한다.
- 전체 코드베이스는 TypeScript를 사용한다.
- UI는 React로 구성한다.
- 시뮬레이션 코어는 UI와 분리된 순수 TypeScript 모듈로 구현한다.
- 엔진은 Dedicated Web Worker에서 실행하여 UI 메인 스레드를 차단하지 않는다.
- Worker는 상태 변화 이벤트를 묶어서 UI에 전달한다.
- UI는 이벤트 버퍼와 별도의 애니메이션 시계를 사용해 상태 변화를 재생한다.
- 빠른 계산 후 재생, 일시정지, 배속 조절, 타임라인 이동을 지원하는 구조로 설계한다.
- 서버 API, 중앙 데이터베이스 및 로그인 기능은 첫 버전에서 사용하지 않는다.

### 7.3 목표 성능 범위

| 항목 | 목표 |
|---|---:|
| 시뮬레이션당 PR 수 | 100~1,000개 |
| 정책당 몬테카를로 반복 | 10~100회 |
| 성능 기준에서 비교할 정책 | 3개. 제품 기능상 최대 개수 제한이 아님 |
| 일반 실험 완료시간 | 사용자 데스크톱 브라우저에서 30초 이내 |
| 애니메이션 | 사용자 브라우저에서 체감상 느리지 않고 UI 조작이 가능한 수준 |

위 완료시간은 정책 3개를 비교하는 대표 성능 기준이다. 사용자는 한 실험에 더 많은 정책 인스턴스를 선택할 수 있으나 실행량은 정책 수에 따라 증가하며, 3개를 초과한 비교에는 30초 완료시간을 보장하지 않는다.\n\n애니메이션에는 고정 FPS나 고정 표시 PR 수를 요구하지 않는다. 브라우저 성능에 따라 이벤트 묶음 크기, 표시 세부도, 생략·집계 수준을 조절할 수 있어야 한다.

### 7.4 범위 밖

- 실제 과거 PR 로그 재생
- 현실 데이터에 대한 모델 보정
- 실제 운영 파일럿 또는 정책 자동 적용
- master 복구·롤백
- 격리 PR 수정 및 재투입
- LLM 내부 앙상블 분석
- PR 크기, 변경 영역, 작성자, 위험도 등 PR별 속성 차이
- PR 간 선후행 의존성

## 8. 검증 기준

검증 목표는 현실 예측 정확도가 아니라 주어진 환경과 정책을 정확하고 재현 가능하게 실행하는 것이다.

### 8.1 불변조건

- 동일 입력과 난수 시드는 동일한 결과를 만든다.
- 단일 CI 자원은 동시에 둘 이상의 작업을 실행하지 않는다.
- 머지와 격리는 정의된 CI 상태 전환으로만 발생한다.
- LLM 결과만으로 격리되지 않는다.
- 격리 또는 머지된 PR은 다시 활성 상태로 돌아가지 않는다.
- 상태별 PR 수의 합은 생성된 전체 PR 수와 일치한다.
- 집계 지표는 이벤트 로그에서 다시 계산한 값과 일치한다.
- 정책에는 허용된 관측 정보만 제공한다.
- 환경값 출처 메타데이터의 유무는 같은 시나리오 숫자와 난수 시드의 결과를 바꾸지 않는다.

### 8.2 극단 조건 검사

- 개별·상호작용 결함이 없고 거짓 양성률이 0이면 정상 후보 master는 실패하지 않는다.
- 거짓 음성률이 1이면 비정상 후보 master도 항상 성공으로 관측된다.
- 거짓 양성률이 1이면 정상 후보 master도 항상 실패로 관측된다.
- LLM 실제 범인 지목 확률이 1이고 오지목 확률이 0이면 모든 실패 원인을 완전히 찾는다.
- LLM 실제 범인 지목 확률이 0이면 실제 실패 원인을 찾지 못한다.

## 11. 구현 단계로 위임한 사항

- PR 도착 간격의 구체적인 확률분포
- 중앙 확률 구간의 프로젝트 기본 포함 확률
- 개별 결함 및 상호작용 집합 생성기의 구체적인 샘플링 방식
- LLM 출력 집합의 구체적인 확률 샘플링 방식
- 기본 몬테카를로 반복 횟수
- 0으로 나누는 지표의 표시 방식
- 파일 형식과 브라우저 저장 구조
- 구체적인 UI 컴포넌트, 시각화 렌더러 및 애니메이션 세부 구현
- Worker 이벤트 묶음 크기와 성능 저하 시 표시 세부도 조절 규칙
- 기본 입력값과 입력 유효 범위
- 세 기준 정책의 구체적인 매개변수와 세부 알고리즘

## 12. 개발 계획 진입 상태

요구사항 수준에서 필요한 조건은 충족됐다.

- 핵심 사용자 결정이 모두 완료됐다.
- 첫 번째 버전의 기준 정책 범위가 정해졌다.
- 엔진과 정책의 책임 및 정책 인터페이스가 정의됐다.
- 필수 환경 입력, 이벤트, 상태 전환, 출력 지표가 정리됐다.
- 구현 단계로 위임할 사항이 명시됐다.

다음 단계는 `/plan`을 사용해 데이터 구조, 엔진 구현, 기준 정책 알고리즘, 검증, 분석 UI 순서로 개발 계획을 설계하는 것이다.
